# Release 0.4.0 plan: iAsset Passport Designer

## Problem
The PO wants five changes:
- Import manually refined Excel designs, turn them into iAsset-like mockups for screenshots, and cross-reference them with the spec.
- Check and fix the annotations in refined sheets.
- Add the spec's object and attribute lists to the export as reference tabs.
- Check field IDs against V2 diverse-fields data, offline.
- Accept the iAsset GUI field-catalog xlsx as an ID source.

## Facts from the research
- **Export:** `excel_export.sheet_layout`/`write_tab`.
  - A1 holds the title and A2 holds `Objecttypes: …`.
  - Sections start at row 4. Headings are in column A with a solid fill (grey D9D9D9, blue D9E2F3 for semantic).
  - Fields are laid out 5 per row with a blank row between.
  - The margin column `Opmerkingen` is G in v3.
  - There is no metadata today.
- **Annotations:** the label suffix `(n)`.
  - Numbers are assigned alphabetically in `layout_engine._object_information`.
  - `tab.footnotes` maps n to object types.
  - The margin text reads `(3) Objecttype: A, B`.
  - `compare.read_manual` already parses refined sheets (`SUFFIX`, `FOOTNOTE_LINE`).
- **Spec reader:** keeps only Objecttype/Attribuut/flag from `Attributen`; `sources` holds file names only. Reference tabs therefore need the raw rows, so the reader will keep the path and re-read them.
- **Field IDs:** `FieldIdMap` (`field_map.py`) maps by label only (json/csv/xlsx). It is used only by `payload.py`.
- **Mockup:** `ui/mockup.py` `PassportMockup` is built from widgets with equal column stretch. Also relevant: `render_pixmap()` for PNG, the dark/light palette in `ui/theme.py`, and the menus in `main_window._build_menus`. Background jobs use `workers.Job`.
- **V2 diverse-fields JSON:** a list of `{id, label, type: select|numeric|input…, values[{value,label}], order, group, mandatory, suffix, themes[{theme, subtheme}]}`.
- **Catalog xlsx:** sheets `Paspoort velden` (Veld ID, Label, Veldtype pulldown/cijferveld…, Naam, Achtervoegsel, Verplicht, …, Bron), `Thema Subthema` (Veld ID, Thema ID, Thema, Subthema ID, Subthema; about 165k rows), `Domeinwaarden` and `Afhankelijkheid`. It is about 4 MB, so it is read with `read_only=True`.
- **No API spec in the repo:** the public spec download is blocked here. Feature 4 is offline, so this is not needed.

## Approach / architecture
New pure-Python modules, unit-testable without Qt:
- `passport_designer/field_catalog.py` (F4/F5): a `FieldCatalog` with `entries: id → FieldInfo(id, label, type, suffix, mandatory, subthemes: set[(theme_id, subtheme_id, subtheme_name?)], values)`.
  - It loads the V2 JSON and the GUI catalog xlsx, and has a normalised type mapping (select↔pulldown, numeric↔cijferveld, input↔tekstveld…). Unknown types are reported, not guessed.
  - `FieldIdMap.load` delegates to it for the catalog xlsx and JSON.
- `passport_designer/id_check.py` (F4): `check_ids(tabs, catalog, id_map?) -> list[IdFinding]` and `export_id_report(findings, path)`.
  - Subthema applicability: object-type name ↔ subthema name (case- and whitespace-insensitive).
  - With V2 JSON input, only subthema IDs are available, without names. The check then reports "subthema names unknown — load catalog xlsx".
- `passport_designer/refined_import.py` (F1/F2): `read_refined(path) -> RefinedWorkbook` containing sheets → `PassportTab`, plus cell coordinates, column widths and `_designer` metadata.
  - Reuses and refactors `compare.read_manual`.
- `passport_designer/crossref.py` (F1): `diff_tab(imported, generated) -> TabDiff` with added, removed, moved (section or position change), renamed (fuzzy match ≥ 0.85) and not-in-spec entries.
- `passport_designer/annotations.py` (F2): `check_annotations(refined, spec) -> list[AnnotationIssue]` and `fix_annotations(path, spec) -> fixed_path`.
  - The fix edits only label suffixes and margin cells, in place on a copy loaded with openpyxl, so styling is preserved.
- `excel_export.py` (F3, D7): `add_reference_sheets(wb, spec, object_types)` and `write_metadata(wb, tabs, spec, profile)` (hidden sheet).
- `spec_reader.py`: keep the source paths and the raw header and rows of `Objecttypen`/`Attributen`, or re-read lazily.

UI (`main_window.py`, `ui/mockup.py`, new `ui/crossref_panel.py`, `ui/id_check_dialog.py`, `i18n.py` NL/EN):
- File menu entries:
  - *Import refined Excel…*: loads the sheets as the current design, shows the diff panel, and has a highlight toggle.
  - *Check/fix annotations…*
  - *Check field IDs…*
  - *Load field IDs…* now also accepts the catalog xlsx.
- The mockup restyle applies to all designs (D5). PNG export keeps working, and highlights are hidden unless toggled.
- Long reads run in `workers.Job`.

## Acceptance criteria (excerpt; full list in the issues)
- **F1:** importing our own export round-trips to an identical design, with an empty diff. Moving, removing, adding or renaming a field in Excel shows up correctly in the diff. Unknown labels are flagged. The mockup renders the imported design with Excel-relative column widths, and the PNG has no highlights unless toggled.
- **F2:** after manual moves the check lists stale numbers and margin rows. The fix produces `_fixed.xlsx`, numbered 1..n in reading order, with each margin text on its field's row and object types matching the spec. Styles and widths are unchanged, and the original file is untouched.
- **F3:** each export contains `Bron Objecttypen` and `Bron Attributen` sheets. They hold the original headers and rows, are filtered to the exported object types, and carry the source and date. The `_designer` sheet is hidden.
- **F4:** the report flags missing IDs, label mismatches, type mismatches and subthema not enabled. It can be exported to xlsx and makes no network calls.
- **F5:** "Load field IDs" accepts the catalog xlsx (`Paspoort velden`, `Veld ID`/`Label`) and keeps subthema data for F4.

## Risks / notes
- Refined files may break the heuristics (merged cells, changed fills, extra columns). Metadata plus clear error reporting mitigate this.
- Footnote numbers are reused by hand across sheets (analysis v3). The fix renumbers per sheet, as stated in D6.
- Field-type mapping between the V2 JSON, the catalog and the spec is partly unknown. Unknown pairs are reported as "unverified", never guessed.
- The spec may not carry a field type. In that case the type check compares catalog against JSON, when both are loaded.
- The catalog xlsx is large: read only the needed sheets in read_only mode, in a background job.
- The PO reference files stay on the `reference/0.4.0-inputs` branch. Tests use only small synthetic fixtures.
- Agents work on the session branch, never call the live iAsset API, and never merge, tag or push to main.
