# 0.5.0-01 Versioned exe name and window title (PO item 7)

Status: done (implemented 2026-11-16; PO approval per the release brief) · Size: S · Builder: **Haiku** · Depends on: –

## Goal
The exe file and the window title carry the version, e.g. `iAsset Passport Designer v0.5.0`.

## Requirements summary (PO decisions D2, D9: exe name with spaces and version)
1. `build.ps1` reads `__version__` from `passport_designer/__init__.py` and produces **`dist\iAsset Passport Designer v<version>.exe`**, e.g. `iAsset Passport Designer v0.5.0.exe`.
2. Both workflows use the same computed name for the build, the SHA256, the artifact and the release upload. No hard-coded `iAsset_Passport_Designer.exe` remains outside CHANGELOG history.
3. The main window title reads `iAsset Passport Designer v0.5.0`, followed by ` – <imported file>` when one is loaded (current behaviour).
4. `APP_NAME` and `QApplication.setApplicationName` stay **unchanged**, so the QSettings and log paths, and with them the saved settings, keep working.
5. The READMEs (NL and EN) describe the versioned name generically (`iAsset Passport Designer vX.Y.Z.exe`).
6. Every script quotes the path, because it contains spaces. The SHA256 file is `iAsset Passport Designer v0.5.0.exe.sha256`, and its content line names the exe exactly.

## Affected modules
`build.ps1`, `.github/workflows/ci-release.yml`, `.github/workflows/release.yml`, `passport_designer/ui/main_window.py` (`_update_title`, l.777), `passport_designer/i18n.py` (`app.title`), README.md, README.nl.md.

## Steps
1. **[Haiku] `build.ps1`**
   - Parse the version with `Select-String '^__version__ = "([0-9.]+)"'` (the same regex as release.yml).
   - Set `$exeName = "iAsset Passport Designer v$version"` and pass `--name "$exeName"` (quoted).
   - Print `dist\$exeName.exe`.
   - Exit with an error if no version is found.
2. **[Haiku] `release.yml`**
   - Compute `$exe` from the tag: `"dist/iAsset Passport Designer $env:TAG.exe"` (the tag is already `vX.Y.Z`), quoted everywhere.
   - Replace the hard-coded paths in the SHA256, upload-artifact and `gh release upload` steps.
3. **[Haiku] `ci-release.yml`**
   - In the `Version` step, also output `exe=dist/iAsset Passport Designer v$version.exe`.
   - Use it **quoted** in `gh release create "$tag" "$exe"`.
   - Optionally add a `.sha256` step like release.yml (ask the Reviewer).
4. **[Haiku] `_update_title`:** `title = f"{tr('app.title')} v{__version__}"` plus the existing suffix. `__version__` is already imported at l.42.
5. **[Haiku] Docs:** update the download and build paragraphs in README.md and README.nl.md.

## Tests
- `tests/test_ui_smoke.py`: `test_window_title_contains_version`. Build `MainWindow` offscreen and assert `f"v{__version__}" in window.windowTitle()`. After a simulated import, the version is still present.
- Add no PowerShell test. The Release Manager smoke-tests `build.ps1` locally and checks the file name.

## Risks
- **Spaces in the name (chosen by the PO, D2):**
  - GitHub may show the release asset as `iAsset.Passport.Designer.v0.5.0.exe` (unverified). The file users download then has dots, while the exe itself works.
  - The Release Manager checks the asset name after publishing and reports it to the PO. A fix is not needed for this release.
  - Every pwsh/bash step must quote the path.
- **Old download links:** links to `iAsset_Passport_Designer.exe` and the `releases/latest/download/...` URLs break. Mention this in CHANGELOG.
- **Do not change `APP_NAME`:** that would orphan the QSettings and log folder.

## Open questions
None. D2 settled the name; the version in the window title is accepted.
