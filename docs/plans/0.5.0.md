# Release 0.5.0 plan: iAsset Passport Designer

Status: **draft**. Only the PO can set a plan to `approved`.
Current version: 0.4.0 (`passport_designer/__init__.py`). Target version: **0.5.0**, chosen by the PO on 2026-11-16 (the earlier draft said 0.8.0).

## PO decisions (2026-11-16)
| # | Decision |
|---|----------|
| D1 | The release is **v0.5.0**. |
| D2 | The exe name has **spaces and the version**: `iAsset Passport Designer v0.5.0.exe`. |
| D3 | **Minimal dataset colours per object type.** In a passport with several object types, MDS fields that do not belong to all types get a distinct colour per object type. The object-type name in the header and legend gets the same colour. Fields that are MDS for all types use the common green. |
| D4 | **Red text and green fill in refined sheets mean "verify with the customer".** These fields may be deleted later. The Design sheet must offer marking them (red text) and deleting them altogether. See plan 10. |
| D5 | **Update `rotterdam_v3`** and keep a **maximum of 5 fields per row** (screen width). |
| D6 | "New row" means **either a blank row or a new titled section**. The **payload follows the Design sheet**, whose choices are leading. |
| D7 | **Folders are user-selected.** Bulk file names are either the **tab name** (e.g. `Dragers.png`) or the **object-type name**. |
| D8 | **Wave-3b grouping** (Filter vs Fase) is ignored for now. |
| D9 | The **menu labels** proposed in plan 09 are accepted. |

## Recommended build order
1. **01 Versioned name**, **02 Light tabs** and **09 Menu labels**: small, isolated (trivial, Haiku), and they make the release visible early.
2. **03 Spec flags**: a pure-core foundation for 04 and 05.
3. **04 Opnemen toggle**, then **05 MDS mask**: they share the lookup helper.
4. **06 Profile refinements**: this changes the generated layout, so it lands before user overrides are stored against it.
5. **07 Drag and drop**: the riskiest feature, built on the final generated layout.
6. **10 Verify marks**: uses the override model from 07.
7. **08 Bulk export**: last, so it exports every toggle (Opnemen, MDS, overrides, verify marks) in one go.
8. Review, docs and release (see below).

01 and 02 can run in parallel with 03. 06 can run in parallel with 04 and 05.

## Facts used (verified 2026-11-16)
- **Spec files** (wave-2, wave-3a, wave-3b and wave-4, dated 20261022–20261106). Every file has the sheets `Objecttypen`, `Attributen` and `Domeinwaarden`, with the header on row 2.
  - `Attributen` columns: A Organisatie, B Objecttype, C Fase, D Klasse, E Volgorde, F Multipliciteit, G Attribuut, **H `Opnemen`**, **I `MinimaleDataset`** (one word), J Informatiemodel, K Datatype, L URI, M Definitie.
  - Every flag value is exactly `Ja` or `Nee`; there are no blanks.
  - `MinimaleDataset = Ja` occurs only with `Opnemen = Ja`, so MDS is a subset of Opnemen.
  - Duplicate type+attribute rows exist (54, 1, 38 and 101 per file) but never with conflicting flags.
  - No object type appears in two waves.
- **`spec_reader.read_spec` reads all four without errors.** `FLAG_COLUMNS = ("in paspoort tonen", "opnemen")` already picks column H. Only `Nee` is kept, in `SpecModel.excluded`; **the MDS column is ignored today.**
- **The PO request in item 1 already partly exists.** The left-panel checkbox *Only attributes marked for the passport* (`design/only_flagged`, `LayoutOptions.only_flagged`, `layout_engine.py:92-95`) skips `Nee` attributes. Plan 04 turns this into the requested toggle.
- **Main tabs** (`main_window._build_ui`): Mockup, Design sheet (Ontwerpblad), API payload, Validation, Merge suggestions, Cross-reference.
  - `SheetPreview` is a read-only `QTableWidget` fed by `excel_export.sheet_layout`. The Excel export uses the same layout, so a fill set in `sheet_layout` appears in both.
  - `PassportMockup.render_pixmap()` renders a non-scrollable copy for PNG.
- **Field order** is generated: alphabetical inside blocks (`layout_engine._object_information`); fixed and relation sections follow the profile. No user override exists, and design edits are not persisted (merges and imports are held in memory only).
- **The "Design profile" is not a tab.** It is a radio submenu under Settings with two hard-coded profiles, Rotterdam v3 and Legacy (`profiles.py`, `main_window.py:347-357`).
- **Theme:** `_apply_theme` only sets an app stylesheet. There is no `setStyle("Fusion")`, no `QPalette` and no colour scheme, so the native Windows 11 style takes tab colours from the system's dark mode.
- **Exe name:** `iAsset_Passport_Designer.exe` is hard-coded in `build.ps1`, `.github/workflows/ci-release.yml`, `.github/workflows/release.yml`, both READMEs and CHANGELOG history.
- **Wave-3b uses the columns differently.** `Filter` holds the category, and `Fase` is the constant "Wave 3b", so all 63 types land in one group. **Out of scope for 0.5.0 (D8).**
- **Orphan types:** `Isolatiekoppeling` (wave-2) and `Waterplanten` (wave-3b) have attributes but no `Objecttypen` row.

## Live-data and safety
The app is offline. No plan calls iAsset or changes live data. The only writes are local files: PNG, xlsx, and the layout JSON in plans 07 and 10. Deleting a field (plan 10) only changes the local design and can be undone. Overwriting existing files always asks for confirmation. The PO's workbooks stay outside the repo; tests use small synthetic fixtures built in `conftest.py`.

## Release steps (no push, merge or tag without PO approval)
1. PO answers the open questions and sets each plan to `approved`.
2. Build per feature, in the order above, on the session branch, one commit per step. Runner runs ruff, pyright and pytest after every step.
3. Reviewer reviews each feature; fixes loop back to the builder.
4. Docs Writer updates README.md, README.nl.md and CHANGELOG.md (`## 0.5.0`, bilingual where the existing file is).
5. Release Manager:
   1. Sets `__version__ = "0.5.0"`.
   2. Runs all checks.
   3. Runs `build.ps1` locally and confirms `dist\iAsset Passport Designer v0.5.0.exe` starts and shows `v0.5.0` in the title, with the light theme correct while Windows is in dark mode.
   4. Writes the SHA256.
6. Release Manager opens a PR to `main` and **stops for PO approval**.
   - **Caution:** merging to `main` triggers `ci-release.yml`, which **automatically creates and publishes release `v0.5.0`** with the exe. Merging is therefore the publish step.
7. After the PO approves, the PO (or the Release Manager on explicit instruction) merges. Then check the release asset names: GitHub may show spaces as dots (unverified; see plan 01). Also check the SHA256 when `release.yml` is used.

Recommended defaults apply unless the PO says otherwise.

**Plan 02 (theme)**

**Plan 04 (Opnemen toggle)**
- **Q-04a:** Should the toggle be in the View menu plus above Mockup/Design sheet, replacing the left-panel checkbox? Recommended: yes.
- **Q-04b:** In "all" mode, show `Nee` fields in grey italic? Recommended: yes.

**Plan 05 (MDS mask)**
- **Q-05b:** Excel fills are opaque; use the light tints listed in plan 05? Recommended: yes.
- **Q-05c:** A field is MDS for 2+ but not all object types. Recommended: stripes in the mockup and a multi-stop gradient in Excel. The alternative is one neutral "mixed" colour with the types in a tooltip.

**Plan 07 (drag and drop)**

- **Q-07c:** Renumber footnotes `(n)` in reading order after a move? Recommended: yes.

**Plan 08 (bulk export)**
- **Q-08b:** May one run select object types across several passport tabs? Recommended: yes.
- **Q-08c:** Should export options default to the current toggles but be adjustable per run? Recommended: yes.

**Plan 09 (menu labels)**

**Plan 10 (verify marks)**
