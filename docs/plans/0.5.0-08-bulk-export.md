# 0.5.0-08 Bulk PNG export tab: passports and/or object types in one go (PO item 3)

Status: done (Q-08d "also export Design sheet as PNG" left out) · Size: M–L · Builder: **Opus** (render loop, cancel, file handling), **Sonnet** (panel UI), Haiku (i18n) · Depends on: 04, 05, 07 (so all toggles and overrides are exported)

## Current state
- *File → Export mockup as PNG…* (`export_png`, main_window.py:1215) saves `self.mockup.render_pixmap()` for the current tab and type only.
- `PassportMockup(scrollable=False)` and `render_pixmap()` already exist. `LayoutEngine.build_single(tab, object_type)` builds a one-type design.
- Widget grabbing must run in the GUI thread, so `workers.Job` (thread pool) **cannot** render. Rendering must be chunked on the GUI thread instead.
- Size: wave-2 has 135 object types and wave-4 has 115, so a full run can be 100+ PNGs.

## PO decision D7 (2026-11-16, verbatim)
"Allow the user to select the folders. If using the bulk feature, the filename can be either the name of the tab (ie dragers) or objecttype."

## Requirements summary
1. **A new main tab, Bulk export** (NL **Bulkexport**), is the 7th tab, in its own module `ui/bulk_export_panel.py`.
2. **Selection tree:** a checkable tree with each passport tab as parent and its object types as children, plus a search box (`Filter…`) and the buttons **Select all**, **Select none** and **Expand all**.
   - A checked parent exports the **passport PNG**, covering all its types.
   - A checked child exports the **object-type PNG**, built with `build_single`.
   - Both can be checked together.
   - Recommended per Q-08b: an object type can be checked across different passports in one run.
3. **Options group:**
   - **Theme:** Dark/Light; defaults to the current theme.
   - **Only fields with Opnemen = "Ja"**: defaults to current.
   - **Highlight minimal dataset**: defaults to current; disabled when the spec has no MDS column.
   - **Show "verify with customer" marks** (plan 10): defaults to current.
   - **Include extra tabs**: defaults to the current View setting.
   - **Cross-reference highlights**: always off in bulk export.
   - Q-08d: **Also export Design sheet as PNG**, default off.
4. **Output (D7):**
   - **Two folder pickers, chosen by the user:**
     - **Folder for passport images…** (NL **Map voor paspoortafbeeldingen…**)
     - **Folder for object type images…** (NL **Map voor objecttype-afbeeldingen…**)
     - They default to the same folder. Each is remembered (`paths/bulk_tabs`, `paths/bulk_types`), and a picker is only required when something of that kind is selected.
   - **File names:** the passport PNG is named after the **tab name** (e.g. `Dragers.png`), and the object-type PNG after the **object-type name** (e.g. `Persleiding.png`). Names are made safe with `safe_filename`.
   - **Collisions:** the same object type selected under two passport tabs, or a type name equal to a tab name in the same folder, gets the tab in brackets: `Persleiding (Dragers).png`. A remaining duplicate gets ` (2)`.
   - Existing files trigger one confirmation (`N files already exist. Overwrite?` with **Overwrite all / Skip existing / Cancel**; NL **Alles overschrijven / Bestaande overslaan / Annuleren**).
5. **Export N images** button. The count updates live. It is disabled when nothing is selected or a required folder is missing.
6. **Progress and cancel:** a progress bar with `Exporting 12 of 140: Persleiding…` and a **Cancel** button. Cancel stops after the current image, keeps the files already written, and reports `Cancelled: 12 of 140 exported.`
7. **Errors:** an error on one image (e.g. a write failure) is logged and listed. The run continues, and the end report shows `Done: 138 exported, 2 failed` with a **Show details** list and an **Open folder** button.
8. **Consistency:** every image is identical to what *Export mockup as PNG* would give for the same selection and options, including the drag-and-drop overrides from plan 07 and the MDS shade from plan 05.
9. **UI stays responsive** during the run. The rest of the UI is disabled except Cancel.

## Design
- **Core:** `@dataclass(frozen=True) class ExportJob: passport: str; object_type: str | None; path: Path`.
- **`plan_jobs(*, selection: Mapping[str, set[str | None]], tab_folder: Path | None, type_folder: Path | None) -> list[ExportJob]`**
  - `None` in a selection set means the passport PNG, named `<tab>.png`; a type is named `<type>.png`.
  - It handles safe names and collisions (`<type> (<tab>).png`, then ` (2)`).
  - It raises `ValueError` when a needed folder is `None`.
- **`existing(jobs) -> list[ExportJob]`**
- **The panel** emits `export_requested = pyqtSignal(object)`, carrying the jobs and options. `MainWindow` owns a `BulkExporter(QObject)`, which:
  - processes one job per `QTimer.singleShot(0, …)` tick;
  - builds the tab with `_effective_tab`/`build_single`;
  - calls the mockup renderer with the options;
  - calls `QPixmap.save` and checks the return value;
  - emits `progress(int, int, str)`, `finished(ExportReport)` and `failed_item(job, message)`;
  - has a `cancel()` method.
- **Rendering** reuses one off-screen `PassportMockup(scrollable=False)` instead of creating 140 widgets, to keep memory flat. `render_pixmap` gets the keyword options `palette`, `minimal`, `legend`, `muted`, `verify` and `show_extra_tabs`, so global UI state is never changed during the run.

## Tests
- **Core (`tests/test_bulk_export.py`):**
  - Job planning: passport only, types only, both, cross-passport.
  - Names: `Dragers.png` for a tab and `<type>.png` for a type.
  - Separate folders, and `ValueError` on a missing folder.
  - Safe names with `/:*?`.
  - Collisions: `<type> (<tab>).png`, then ` (2)`.
- **UI (offscreen, `tests/test_ui_smoke.py` or the new `tests/test_bulk_export_ui.py`)**
  - **Full run:** load a synthetic spec with 2 passports and 3 types.
    1. Check one passport and two types in the real tree.
    2. Set the folder to `tmp_path`.
    3. Click **Export 3 images**.
    4. Process events until done, using `qtbot`-free polling with `QApplication.processEvents` and a timeout.
    5. Assert 3 PNGs exist with non-zero size, and that the report shows 3 exported.
  - **In-progress state:** after starting, the Export button is disabled, Cancel is enabled, and the progress text matches `Exporting 1 of`.
  - **Cancelled:** click Cancel after the first tick. Fewer files than planned exist, and the report says `Cancelled`.
  - **Error:** monkeypatch `QPixmap.save` to return False for one job. The report shows 1 failed, and the others are written.
  - **Overwrite:** pre-create a file, choose *Skip existing* (monkeypatched dialog), and the file is untouched.
  - **Consistency:** the bulk PNG equals the single *Export mockup as PNG* output for the same selection (same size, pixel hash).
  - **MDS on:** the shaded pixel is present in the bulk PNG.

## Risks
- **Performance and memory:** 140 renders at `EXPORT_WIDTH` take seconds, not minutes. Reuse one widget and call `deleteLater` on per-job children. Measure with the wave-2 spec locally (not in CI).
- **The GUI thread is mandatory for `grab()`.** Do not move rendering into `workers.Job`.
- **Wave-3b grouping** (see plan 06, pointer 17) makes "per passport" one huge PNG. Very tall images may exceed the PNG or QPixmap size limits (about 32k px). Report "too large" as a per-item error instead of crashing (Opus step 3).
- No live data: local files only, with an overwrite confirmation.
