# 0.5.0-07 Drag and drop field reordering and new rows/groups in the Design sheet (PO item 5)

Status: draft · Size: L · Builder: **Opus** (all core and UI-interaction steps), Haiku (i18n and docs) · Depends on: 06

## Current state
- `SheetPreview(QTableWidget)` is read-only (`NoEditTriggers`, sheet_preview.py:28). It renders `excel_export.sheet_layout(tab)`, a list of `SheetCell(row, col, …)` that carries no link back to section, row and cell.
- Field order is generated on every rebuild (`layout_engine._object_information`, alphabetical), and nothing user-made is persisted. Rebuilds happen on profile, filter, toggle and merge changes.
- The Mockup, Excel export, PNG and payload all consume `PassportTab.sections[*].rows`. **If the reorder is applied to the `PassportTab`, every output follows automatically.**

## PO decision D6 (2026-11-16, verbatim)
"Either a blank row or a new titled section. The payload must definitely change too, the design sheet choices are leading." D5 also applies: a row holds at most 5 fields.

## Requirements summary
1. **Drag a field to a new position.** In the Design sheet, a field cell can be dragged to another position in the same or another section of the same passport tab. A drop indicator shows the target. Dropping between two fields inserts; dropping on a field moves before it.
2. **The Design sheet is leading; every output follows immediately.** After the drop, the Mockup, Design sheet, Excel export, PNG and **API payload** all show the new order and the new rows and sections. The payload has no separate ordering.
3. **Context menu on a cell or row.** All actions, NL + EN:

   | English | Nederlands |
   |---|---|
   | **Insert empty row above** | **Lege rij erboven invoegen** |
   | **Insert empty row below** | **Lege rij eronder invoegen** |
   | **New section below…** | **Nieuwe sectie eronder…** |
   | **Rename section…** | **Sectie hernoemen…** |
   | **Delete empty row** | **Lege rij verwijderen** |
   | **Reset order of this passport** | **Volgorde van dit paspoort herstellen** |

   - *New section below…* asks for a title (required, max 60) and a style: Plain/Sem.Rel. Fields can then be dragged into the new section. In the payload a new section becomes a section header element with that title, plus a line between sections; the same `payload.section_element` classification applies as for generated sections. The Reviewer checks this.
   - A **blank row** separates groups. It is exported as a blank row in Excel and the mockup, and becomes the payload's blank or separator element where the payload supports one; otherwise it is skipped in the payload (Reviewer verifies against `payload.py`). An empty new section shows a dashed drop placeholder and is not exported while empty.
4. **Grid limit (D5).** A row holds at most `profile.grid_columns` (5) fields. Dropping on a full row is refused with the status message `Row is full (max 5 fields). Insert an empty row first.` (NL `Rij is vol (max. 5 velden). Voeg eerst een lege rij in.`).
5. **Undo.** Ctrl+Z undoes and Ctrl+Y redoes layout edits (a `QUndoStack`, per passport). *Edit → Undo/Redo* are menu actions.
6. **Persistence (Q-07b).** Layout edits survive rebuilds and restarts:
   - They are stored as an override per passport tab (key = tab name + profile key), autosaved in the app data folder per spec-set fingerprint (sorted source file names).
   - *File → Save layout…* / *Load layout…* exchange a JSON file.
   - The override is also written into the `_designer` metadata sheet, so refined-import round-trips keep it.
7. **Robust against spec changes.** Fields in the override that no longer exist are dropped and reported in the Validation tab (`Layout: field "X" no longer in specification`). New spec fields not in the override are appended at their generated position (end of their section) and listed as validation info.
8. **Footnotes** `(n)` are renumbered in reading order after edits (Q-07c), with the `Opmerkingen` margin following its row.
9. Only the Design sheet supports dragging. The Mockup is a view. Editing is disabled while an imported refined sheet is shown, or it applies to the imported tab too (decision in review; recommended: allowed).

## Design (core, no Qt)
New module `passport_designer/layout_overrides.py`:
```python
@dataclass(frozen=True)
class CellRef:            # positie in een PassportTab / position in a PassportTab
    section: int
    row: int
    col: int

@dataclass
class SectionOverride:
    title: str
    style: SectionStyle
    rows: list[list[str]]          # genormaliseerde labels; [] = lege rij / normalised labels; [] = blank row
    added: bool = False            # door gebruiker toegevoegd / user-added section

@dataclass
class TabOverride:
    tab: str
    profile: str
    sections: list[SectionOverride]
    version: int = 1

def capture(tab: PassportTab, *, profile: str) -> TabOverride: ...
def apply_override(tab: PassportTab, override: TabOverride) -> tuple[PassportTab, list[str]]: ...   # (new tab, warnings)
def move_cell(override: TabOverride, *, source: CellRef, target: CellRef, max_columns: int) -> TabOverride: ...
def insert_row(override: TabOverride, *, section: int, row: int) -> TabOverride: ...
def add_section(override: TabOverride, *, after: int, title: str, style: SectionStyle) -> TabOverride: ...
def renumber_footnotes(tab: PassportTab) -> PassportTab: ...
def to_json(overrides: dict[str, TabOverride]) -> str: ...
def from_json(text: str) -> dict[str, TabOverride]: ...   # raises LayoutFileError with user message
```
- **Pure functions** that return new objects; the undo stack holds snapshots.
- **Fixed and repeater sections** (Actoren, Memo, Inwinningsinformatie) can move as a whole but their inner cells are locked. Moving cells inside them is refused, because the iAsset payload codes depend on them.
- **Pipeline:** `LayoutEngine.build_all` → `apply_merges` → **`apply_override`** → `renumber_footnotes` → views/exports. A single function, `MainWindow._effective_tab(tab)`, is used by `_refresh_views`, the exports, the payload and the bulk export (plan 08).

2. **[Opus] Cell mapping:** extend `excel_export.SheetCell` with `ref: CellRef | None = None` (and a section index for headings). `sheet_layout` fills it, so the preview can map a table cell back to the model.

   - Enable drag (`setDragEnabled`, `setAcceptDrops`, `DragDropMode.DragDrop`, `Qt.DropAction.MoveAction`).
   - Override `startDrag`/`dragMoveEvent`/`dropEvent`, and never let Qt move the items itself.
   - Emit `move_requested = pyqtSignal(object, object)` (source `CellRef`, target `CellRef`), plus the signals `insert_row_requested`, `add_section_requested` and `reset_requested`.
   - Add the context menu.
   - The panel talks to `MainWindow` only through these signals.
4. **[Opus] `MainWindow` integration**
   - Add `self.overrides: dict[str, TabOverride]` and a `QUndoStack` per tab.
   - Add `_effective_tab`, and route every consumer through it: `_refresh_views`, `export_png`, `export_excel`, `export_excel_per_type`, payload, `preview_tab`.
   - The *Edit* menu gets Undo and Redo.
5. **[Sonnet] Persistence**
   - Autosave as JSON in `data_dir()/layouts/<fingerprint>.json` after every edit (debounced 500 ms), and load it after the spec loads.
   - Add *Save layout…/Load layout…* to the File menu, with an overwrite confirmation.
   - Include the override in `write_metadata` (`_designer` key `layout_json`), and read it back in `refined_import`.
6. **[Haiku] i18n and status messages:** all labels above, NL + EN.

## Risks
- **Highest-risk feature.** QTableWidget's drag and drop moves items by default, so all native moves must be suppressed and every change made through the model. This needs tests on the real widget.
- **Order changes alter the payload.** It stays local; nothing is sent to iAsset. The payload still needs a re-check by the Reviewer against the `payload.section_element` classification.
- **Rebuilds** (profile, filter, merges, Opnemen toggle) must re-apply overrides. A profile switch uses a different override key, so the profile is part of the key.
- **Saved data:** new files in the app data folder, with no secrets. Use a versioned JSON schema (`version: 1`).
- **Large tabs** (wave-2 has 135 types): full rebuilds on every drop should still be fast. Measure, and if needed refresh only the current tab.
