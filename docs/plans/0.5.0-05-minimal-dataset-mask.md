# 0.5.0-05 Minimal-dataset mask: coloured shade per object type on Mockup and Design sheet, also in exports (PO item 2)

Status: draft · Size: M · Builder: **Sonnet**, **Opus** for step 3 (multi-colour rendering) · Depends on: 03 (and shares `dataset_flags.py` with 04)

## PO decision D3 (2026-11-16, verbatim)
"Use different colors for minimal datasets if the object types are not the same. Give the objecttype name the same color so you can see to what the minimal dataset field belongs."

## Requirements summary
1. A checkable action **View → Highlight minimal dataset** (NL: **Beeld → Minimale dataset markeren**), shortcut Ctrl+Shift+M, plus a checkbox in the view toolbar row from plan 04. It is off by default and persisted as `view/minimal_dataset`.
2. **Colour rules** for a passport tab with object types T1…Tn, or the single type selected in the type combo:
   - MDS for **all** types of the tab (or the tab has one type): **common green**. Mockup `rgba(47,168,79,0.28)`, Excel and Design sheet `C6EFCE`.
   - MDS for **exactly one** type Tk, while the tab has several types: the **colour of Tk**.
   - MDS for **several but not all** types: **stripes** of those types' colours. Mockup: a `qlineargradient` with hard stops. Excel and Design sheet: a multi-stop `GradientFill`, with the Excel rendering unverified; see Q-05c for the fallback.
   - The tooltip always reads `Minimal dataset for: <types>` (NL `Minimale dataset voor: <typen>`).
3. **Object-type colours:** a fixed, ordered palette of light tints, assigned in the order of `tab.object_types`. The palette must not use green (common), red (verify marks, plan 10), the heading grey `D9D9D9` or the Sem.Rel blue `D9E2F3`. Proposal: `FFE699` yellow, `F8CBAD` orange, `CCC0DA` lavender, `B7DEE8` teal, `FFCCFF` pink, `D9C3A5` sand, `C9C9F5` periwinkle, `E2E2B5` olive. Mockup versions use about 35 % alpha. Beyond 8 types the colours repeat, and the tooltip still names the types.
4. **Object-type legend in the same colour.** When the toggle is on and the tab has more than one type:
   - Mockup: under the header, each object-type name is a chip filled with its colour, with a final chip `All types` (NL `Alle typen`) in green.
   - Excel: a legend row under `Objecttypes:` with one cell per object type, filled with its colour, plus an `All types` cell in green.
   - Design sheet: shows the Excel legend (same `sheet_layout`).
5. **Export follows the toggle.** When on, *Export mockup as PNG*, the Excel export (all three variants) and the bulk export (plan 08) include the shades and the legend. When off, neither appears.
6. When the loaded spec has no MDS column (`has_minimal_flags` is False), the action is disabled, with the tooltip `The loaded specification has no "MinimaleDataset" column.`
7. The shade is a fill and the crossref highlight is an outline, so both can be visible together. Verify marks (plan 10) use red **text**, which stays readable on every tint.
8. `_designer` metadata records `minimal_dataset_shown: true|false`.

## Steps
1. **[Sonnet] Core lookup and colour plan** in `dataset_flags.py` (no Qt):
   - `def minimal_labels(spec: SpecModel, *, tab: PassportTab, object_type: str | None = None, resolve: Callable[[str], str] | None = None) -> dict[str, list[str]]` returns normalised label → the object types for which MDS is Ja.
     - Labels are matched with `norm(cell.label)`; cells already carry the spec attribute name, as in `layout_engine.py:213-216`.
     - Fixed-section labels (e.g. `naam`) match too when the spec flags them.
     - `ELLIPSIS` and empty cells are skipped.
   - `MDS_TYPE_COLOURS: tuple[str, ...]` (hex, no `#`) and `MDS_COMMON = "C6EFCE"`.
   - `@dataclass(frozen=True) class MinimalMark: colours: tuple[str, ...]; types: tuple[str, ...]`. One colour means a solid fill; several mean stripes.
   - `def minimal_marks(labels: dict[str, list[str]], *, tab_types: list[str]) -> tuple[dict[str, MinimalMark], dict[str, str]]` returns (label → mark, type → colour legend), applying the rules above.
2. **[Sonnet] Excel layout and legend**
   - `excel_export.sheet_layout(tab, *, muted=None, minimal: dict[str, MinimalMark] | None = None, legend: dict[str, str] | None = None)`.
   - `SheetCell` gets `fill_stops: tuple[str, ...] = ()` for stripes. `write_tab` writes a `PatternFill` for one colour and an openpyxl `GradientFill(type="linear", degree=0, stop=…)` with doubled stops (hard bands) for several.
   - The legend row goes under `Objecttypes:`.
   - `export_workbook(..., *, minimal_by_tab: dict[str, tuple[dict[str, MinimalMark], dict[str, str]]] | None = None)`.
3. **[Opus] Preview and mockup rendering**
   - `SheetPreview` paints a `QLinearGradient` background for `fill_stops`. A `QTableWidgetItem` brush can take a gradient brush; verify this.
   - `PassportMockup.show_tab(..., *, minimal: dict[str, MinimalMark] | None = None, legend: dict[str, str] | None = None)`:
     - Apply the solid or striped stylesheet background in `_head`, `_value_box` and `_build_table`, next to the existing highlight lookup (mockup.py:397, 530, 550), plus the tooltip.
     - Show the legend chips under the header.
     - `render_pixmap` copies both.
   - Add `MINIMAL_ALPHA = 0.35` to `theme.py`.
4. **[Haiku] Main window wiring**
   - Add the action and checkbox, plus `_on_minimal_toggled` (save the setting, then `_refresh_views`).
   - `_refresh_views` computes the marks for the shown tab and the selected type.
   - The exports pass `minimal_by_tab` when the toggle is on.
   - Enable or disable the action after the spec loads.
   - Add the i18n keys `action.minimal_dataset`, `action.minimal_dataset_tip`, `minimal.tooltip`, `minimal.all_types` and `minimal.unavailable` (NL + EN, texts above).

## Risks
- **Readability:** tints on the dark mockup palette must stay readable. The Reviewer checks screenshots in both themes.
- **Colour blindness:** the palette is chosen for distinct lightness and hue. The tooltip and legend always give the type names.
- **Excel gradients:** multi-stop `GradientFill` rendering in Excel is unverified. The fallback is Q-05c.
- **Many types:** the legend row on tabs with many types (e.g. 20+) gets wide. It wraps over several rows of 5, matching the grid.
